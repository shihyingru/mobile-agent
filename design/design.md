# Plans & Suggestions — Component Spec

> Implementation reference for **PlanCard**, **PlanEmptyCard**, **SuggestedSection**, and the **Plan modification page**. Pair this with `DESIGN_SYSTEM.md` — all tokens (`bg`, `card`, `ink`, `accent`, `gold`, type stacks, etc.) come from there. Sizes use **dp** for Compose / **px** for web. Both themes are supported.

---

## 1. Data model

### 1.1 `Plan`

A short-lived task list scoped to a date window. The user spins one up for a trip, project, or short stretch.

```kotlin
data class Plan(
  val id: String,
  val title: String,                 // "Android XR submission"
  val start: LocalDate,              // inclusive
  val end:   LocalDate,              // inclusive
  val todos: List<PlanTodo>,         // ordered, 0..n
)

data class PlanTodo(
  val id: String,
  val title: String,
  val done: Boolean = false,
)
```

Derived state (compute once at read time):

| Field      | Formula                                                       |
|------------|---------------------------------------------------------------|
| `total`    | `max(1, daysBetween(start, end))`                             |
| `elapsed`  | `clamp(daysBetween(start, today), 0, total)`                  |
| `daysLeft` | `max(0, daysBetween(today, end))`                             |
| `ratio`    | `elapsed / total` (0..1, clamped)                             |
| `urgent`   | `daysLeft == 0`                                               |
| `done`     | count of `todos` where `done == true`                         |

### 1.2 `Suggestion`

An agent-generated proposal about the user's queue. Inline, not card-shaped.

```kotlin
data class Suggestion(
  val id: String,
  val kind: SuggestionKind,          // MOVE | DEMOTE | SPLIT
  val target: String,                // task title the suggestion is about
  val title: String,                 // imperative — "Move "Gemini Xprize entry" to Thu, May 28"
  val reason: String,                // one sentence, sentence-case
)

enum class SuggestionKind { MOVE, DEMOTE, SPLIT }
```

The set is regenerated by the briefing run; the UI treats it as ephemeral (state lives in memory, not persisted past dismissal).

## 2. PlanCard

### 2.1 Anatomy

```
┌─────────────────────────────────────────────────────┐
│  PLAN · MAY 25 – MAY 30          ⌛ 3 days left     │   ← eyebrow + chip
│  Android XR submission                              │   ← title (display serif)
│                                                     │
│  ───●─────────────────────────────────              │   ← time progress bar
│                                                     │
│  ●  Draft catalyst-program pitch                    │   ← done (line-through)
│  ───────────────────────────────                    │
│  ○  Record 90-second demo clip       Promote ↗      │   ← open + Promote
│  ───────────────────────────────                    │
│  ○  Send draft to Maya for review    Promote ↗      │
│  + 2 more                                       ›   │   ← chevron (corner)
└─────────────────────────────────────────────────────┘
```

### 2.2 Shell

| Property     | Value                                                       |
|--------------|-------------------------------------------------------------|
| Surface      | `card`                                                       |
| Border       | `1 px` `cardEdge` — `hover` lifts to `8,58,79 @ 18%` / `192,213,214 @ 22%` |
| Radius       | `18 dp`                                                      |
| Padding      | `16 dp`                                                      |
| Shadow       | `card.shadow`                                                |
| Tap target   | **Entire surface** — opens Plan modification page            |
| Hover state  | Border darkens + `translateY(-1px)` over 180 ms ease-out     |
| Focus ring   | Use platform default outline                                 |

### 2.3 Header

**Eyebrow row** — mono caps, on one line:
- `PLAN` · `MMM D – MMM D`
- `MONO 9.5 sp · 500 · letter-spacing 1.8 px · UPPERCASE` for "PLAN"
- Date portion: `MONO 10 sp · letter-spacing 0.4 px` (not uppercased)
- Separator dot: `·` at 40 % opacity
- Color: `inkMute`

**Title** — `display.title.md`-ish:
- `Instrument Serif 24 sp · 400 · line 1.1 · letter-spacing -0.2 px`
- Color: `ink`
- Wraps freely; no max-lines (let the title breathe)

**Days-left chip** — sits top-right, vertically aligned to the title block start:
- Pill, `padding 4 / 9`, radius `999`
- Icon: `hourglass` (11 sp, stroke 1.8)
- Text: `Inter 11 sp · 600 · letter-spacing 0.2 px`
- **Normal:** bg `gold @ 16%` (`rgba(165,141,102,0.16)`), fg `gold`
- **Urgent** (`daysLeft == 0`): bg `accentSoft`, fg `accent`, label flips to `"Due today"`
- Pluralization: `"1 day left"` / `"3 days left"`

### 2.4 Time progress bar

A 2 px track with a 10 dp circular today-dot.

| Layer        | Value                                                       |
|--------------|-------------------------------------------------------------|
| Track        | `cardEdge`, `height 2 dp`, `radius 1 dp`, full width        |
| Fill         | `accent`, `width = ratio × 100%`                            |
| Today dot    | `10 dp` circle, `accent` fill, `3 dp` ring in `card` color  |
| Container    | `height 10 dp` (so the dot fits without overflow), `margin-top 4 dp` |

The dot sits at `left: calc(ratio * 100% - 5dp)`. Clamp the ratio to `[0, 1]`.

### 2.5 Todo rows

Up to **3 rows** rendered. If more, append `"+ N more"` line (sans, 12 sp, `inkMute`, top padding 8 dp).

Each row:
- `padding 4 dp top/bottom`, gap `12 dp`
- Divider between rows: `1 px cardEdge`, `margin 8 dp 0`
- **Checkbox** — see §2.7. Click stops propagation (does not open the card).
- **Title** — `Newsreader 15.5 sp · line 1.3 · letter-spacing -0.1 px`
  - Done: `inkMute` color + line-through (decoration color `inkMute`)
  - Not done: `ink` color
- **Promote action** — only when `!done`, right-aligned:
  - `Inter 12 sp · 600`, color `accent`
  - Label `"Promote"` + `arrow-up-right` icon at 12 sp
  - Hit target padding `4 / 6`, radius `6`
  - Click stops propagation; calls `onTogglePromote(planId, todoId)`

**Promote semantics**: pulls the sub-task into today's task list (Home → Today). The plan row remains for reference but reads as "promoted" (greyed Promote button, or removed depending on host behavior).

### 2.6 Corner chevron

The only "edit" affordance — the entire card is the tap target so don't render an "Edit plan" button.

- `chevron` icon, 14 sp, stroke 1.8
- Color `inkMute`, opacity `0.45` resting → `1.0` on hover
- Position: `bottom 12 dp · right 14 dp`
- Slides `translateX(2px)` on hover (180 ms ease-out)

### 2.7 Checkbox

| State | Visual                                                            |
|-------|-------------------------------------------------------------------|
| Off   | 18 dp circle, `1.5 px` ring in `inkMute @ 70%`, transparent fill  |
| On    | 18 dp circle, `accent` fill, white check (60 % of size, stroke 3) |

Stroke path: `M5 12.5l4.5 4.5L19 7.5` in a 24-vbox.

### 2.8 States

| State        | Treatment                                                       |
|--------------|------------------------------------------------------------------|
| Default      | All rules above                                                  |
| Urgent       | Chip flips gold → accent; "Due today" label                      |
| Overflow     | "+ N more" line if `todos.length > 3`                            |
| All done     | Title stays normal weight; rows render line-through; no Promote  |
| Empty todos  | Skip the rows section entirely; the time bar still renders       |

## 4. SuggestedSection

Inline list — **not** a card. Mirrors the BRIEFING block: mono eyebrow followed by *n* rows separated by hairline dividers. Visually parallel to the briefing so the rhythm of Home reads: BRIEFING (read) → SUGGESTED (decide) → PLAN (track).

### 4.1 Section layout

| Property     | Value                                                       |
|--------------|-------------------------------------------------------------|
| Padding      | `0 dp · 4 dp` (sits flush with sibling sections)            |
| Section gap  | Inherits Home's `column gap 18 dp`                          |

### 4.2 Eyebrow

Row: label left, meta right.

| Side  | Type                                                        | Color    | Text                           |
|-------|-------------------------------------------------------------|----------|--------------------------------|
| Left  | `MONO 10 sp · 600 · letter-spacing 1.8 px · UPPERCASE`      | `accent` | `"Suggested"`                  |
| Right | `MONO 9.5 sp · letter-spacing 0.4 px`                       | `inkMute`| `"<model> · N change(s)"`      |

Model string defaults to `"gemini-2.5"`. Pluralization: `"1 change"` / `"2 changes"`.

### 4.3 Row anatomy

```
┌──┐  *Move "Gemini Xprize entry" to Thu, May 28*
│↗ │  Title is incomplete — the brief needs a clearer angle
└──┘  before you start.
     ✓ Apply   Dismiss
─────────────────────────────────────────────────────
```

| Element       | Treatment                                                                 |
|---------------|---------------------------------------------------------------------------|
| Glyph chip    | 26 × 26 dp square, radius `8 dp`, bg `accentSoft`, fg `accent`, icon 14 sp/stroke 1.8 |
| Title         | `Newsreader italic 17 sp · line 1.3 · letter-spacing -0.1 px`, `ink`     |
| Reason        | `Inter 13 sp · line 1.45`, `inkSoft`, margin-top `4 dp`                  |
| Apply         | `Inter 13 sp · 600`, color `accent`, padding `6 / 10`, radius `8 dp`     |
|               | Leading `check-tiny` icon (14 sp, stroke 2)                              |
| Dismiss       | Same shell as Apply but color `inkMute`, no icon                          |
| Action row    | margin-top `8 dp`, margin-left `-10 dp` (offsets first button padding)   |
| Row gap       | Outer: 12 dp between glyph and text block                                |
| Row spacer    | 14 dp below each row                                                      |
| Divider       | `1 px cardEdge` between rows (not above the first), margin `4 dp 0 14 dp`|

### 4.4 Kind → glyph map

| Kind     | Icon                | Notes                                               |
|----------|---------------------|-----------------------------------------------------|
| `MOVE`   | `arrow-up-right`    | Reschedule to a different day                       |
| `DEMOTE` | `arrow-down`        | Drop priority high → med, or med → low              |
| `SPLIT`  | `split`             | Break a task into two                               |

Icon paths (24-vbox, fill none, currentColor, round caps/joins):
- `arrow-up-right` — `M7 17L17 7M9 7h8v8`
- `arrow-down` — `M12 5v14M6 13l6 6 6-6`
- `split` — `M6 4v4a4 4 0 004 4h4a4 4 0 014 4v4M14 4l4 0 0 4M10 20l-4 0 0-4`
- `check-tiny` — `M5 12.5l4.5 4.5L19 7.5`

### 4.5 Interactions

| Action  | Behavior                                                                 |
|---------|--------------------------------------------------------------------------|
| Apply   | Removes the row from the list (optimistic). Host commits the change to the queue (move task / lower priority / split). |
| Dismiss | Removes the row. No queue mutation.                                      |
| Empty   | If `items.length == 0` after filter, the entire section renders nothing — do **not** render an empty shell. |

## 5. Plan modification page

### 5.1 Navigation

Pushed from Home when the user taps a `PlanCard` or `PlanEmptyCard`. Back chevron returns to Home; deleting also returns to Home.

### 5.2 Layout

```
┌────────────────────────────────────────────┐
│  ‹  PLAN                                   │   ← top bar
│                                            │
│  Android XR submission ✎                   │   ← display title (rename)
│  *3 days left, 2 of 5 elapsed.*            │   ← italic status
│  ───●────────────────────                  │   ← time bar
│                                            │
│  ┌──────────┐  ┌──────────┐                │
│  │ Start    │  │ End      │                │   ← two date fields
│  │ May 25 …│  │ May 30 …│                │
│  └──────────┘  └──────────┘                │
│                                            │
│  TASKS                       2/3 done      │   ← section label + count
│  ┌────────────────────────────────┐        │
│  │ ● Draft catalyst-program …  × │        │   ← editable rows
│  │ ──────────────────────────────│        │
│  │ ○ Record 90-second demo …   × │        │
│  │ ──────────────────────────────│        │
```

### 5.8 Delete plan

Two-step destructive. Lives below the tasks card with `margin-top 8 dp · padding-x 4 dp`.

**Step 1 — outlined affordance:**

| Property | Value                                                       |
|----------|-------------------------------------------------------------|
| Surface  | Transparent, border `1 px cardEdge`, radius `14 dp`         |
| Padding  | `12 dp · 14 dp`, width 100 %                                |
| Layout   | Centered row: trash icon (16 sp, stroke 1.7) + label gap 8 dp |
| Label    | `Inter 13 sp · 600`, color `#E5484D` (system red)           |

**Step 2 — inline confirmation card** (replaces step 1 in place):

| Property | Value                                                       |
|----------|-------------------------------------------------------------|
| Surface  | `rgba(229,72,77,0.08)` (red @ 8 %)                          |
| Border   | `1 px rgba(229,72,77,0.35)`                                 |
| Radius   | `14 dp`                                                     |
| Padding  | `14 dp`                                                     |
| Message  | `Newsreader italic 14.5 sp · line 1.4`, `ink`, ends with `"This can't be undone."` |
| Actions  | Right-aligned row: `Cancel` (`inkSoft`, 13 sp, 600) + `Delete plan` (`#E5484D` bg, white fg, 13 sp, 600, padding `8 / 14`, radius `10 dp`) |
| Tap "Delete plan" | Calls host `deletePlan(planId)` and pops back to Home |
| Tap "Cancel"      | Returns to Step 1                                  |

Never destroy data in one tap.

## 6. Integration on Home

The order on Home is:

1. Greeting + status (existing)
2. **BRIEFING** block (existing)
3. **SUGGESTED** section (this spec, §4)
4. **PLAN(S)** — one `PlanCard` per active plan, or a single `PlanEmptyCard` when `plans.isEmpty()`
5. **TASK** cards (existing — Today's queue)

Section padding: `0 dp · 4 dp` to match siblings; gap between sections: `18 dp` (Home column gap).

## 8. Accessibility

- All tap targets meet 44 × 44 dp minimum
- Card surfaces use `role="button"`, are keyboard-focusable, and handle `Enter` / `Space`
- Checkbox uses `role="checkbox" aria-checked`
- Dynamic states (urgent chip, hover lift) never carry information by color alone — chip *text* changes to `"Due today"`
- Striking through completed todos is paired with `inkMute` color and `aria-checked=true`
- Date fields announce the parsed long-form date (`"May 25, 2026"`) for screen readers, not the ISO string

---

## 9. Don'ts

- ❌ Don't render an "Edit plan" link in the card footer — the whole card is the tap target.
- ❌ Don't render a heading row above Plans on Home ("PLANS · N ACTIVE"). The card eyebrow carries that information.
- ❌ Don't render the SuggestedSection shell when there are zero items.
- ❌ Don't allow single-tap delete on the modification page — always require step-2 confirmation.
- ❌ Don't reuse the days-left chip color for SuggestedSection or anywhere else — it's specific to plan urgency.
- ❌ Don't put the composer in a separate card — it lives inside the same tasks card, pinned to the bottom.
